01 · 一句话定位

统一事件页面 / 角色化视图

飞书页面不是系统本身，而是经营事件与证据库在协作侧的一面镜子。

统一事件页面 / 角色化视图 ＋ 飞书原生任务、审批、消息和 Agent 追问入口 ＋ 企业后台事件库、证据库、语义服务和确定性计算服务。

推荐产品形态，原文照录。不推荐把所有内容硬塞进多维表格，也不推荐重做飞书任务和审批。

三个模块共用一个飞书入口，但不共用一套虚构数据：01 投影经营事件与证据库，02 未来投影能力进化记录，03 未来投影扩域治理记录。飞书页面始终是协作投影，不是 SAP、POS、经营事件库或未来能力/扩域记录的第二套权威账。

02 · 数据主链

从权威事实到案件状态，再到决策与验证

一条主链走完全程；任何一环都不允许页面或 Agent 替权威系统补写事实。

SAP/POS/WMS/CRM/飞书等权威事实
→ 数据更新通道 → 语义对象和关系 → 异常检测规则
→ CandidateSignal → 事件解析 → EventPackage v1
→ case_id / CaseState.current_case_state
→ Agent 查询与证据
├─ 事件语义未变化：继续当前案件
└─ 新增/修正事实或新证据提示语义可能变化：Agent 只提交重新解析请求
   → KWeaver 语义层重新解析
   → 确认变化后才输出 EventPackage v2/v3 并更新当前版本
→ DecisionPackage / Approval / Task
→ Milestone / Verification
→ 关闭、重开和复盘

版本边界（已确认）：Agent 只能提交新证据或重新解析请求，不得自行生成、改写或覆盖经营事件包；v2/v3 只能由 KWeaver 语义层重解析后输出并保留旧版本。

看板组件到接口的最低映射，以及不能做的事

每个组件都回答三个问题：读什么、写什么、永远不能做什么。

05 · 三角色看见什么

同一套案件数据，三种身份首页

三角色身份投影，而不是三套数据；摘要默认可见，原始证据按权限下钻。

一线责任人

本人责任任务与授权案件；只看履责所需摘要，敏感经营原始证据无权查看。

区域负责人

所辖区域案件、区域责任、补证进度和升级动作；跨区数据不进入本视图。

集团管理层

案件全局摘要、管理决定、影响状态和跨区汇总；原始证据仍按源系统权限控制。

已确认决策（confirmed）：同一套案件数据按登录身份呈现一线、区域、集团三种首页；管理层汇总并列展示案件治理线和经营影响线。

默认分类（confirmed）：以每个案件唯一的 current_case_state 为主——调查取证中、待人工补证、待补证事实汇总已形成、补证材料完整性确认、分析中、决策就绪、已知悉暂不处理、风险接受、执行中、未解决专项协作、待结果验证、已正式关闭。「案件已建立」、管理决定、任务完成/失败/超时、正式关闭和重开作为里程碑进入时间线，不另造当前状态。

状态分离（confirmed_design）：current_case_state、milestone_code、task_completion_status、collaboration_status、resolution_status、projection_status 分别保存，任一字段不能替代其他字段；页面只投影经营事件与证据库，不能用任务完成冒充经营结果达成。
